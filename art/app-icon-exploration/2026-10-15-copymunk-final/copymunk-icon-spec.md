u = (x - 100.352) / 823.296
v = (y - 100.352) / 823.296
长度归一化 = 长度 / 823.296

16px 扩大圆眼和主高光，保留单条纵冠纹及两块连续奶油鼓腮；删除副高光、侧纹、模糊阴影和嘴内牙舌。开心嘴保留暗色小开口，避免细牙在不足一个像素的区域内把嘴抹淡。毛色采用 `#EAB781 → #D99A63 → #AD643C` 的简化渐变，腮部采用 `#FFF5DD → #EDC899`，眼睛固定为 `#30221B`。

32px 鼻嘴之间保留约 `0.95px` 的净空，主高光清楚可见。开心嘴为约 `2.9×1.5px` 的横向小开口，保留一颗小门牙，删除细舌部；避免细长深点被读成 O 型嘴。只在耳根外侧保留很淡的短纹；去掉主图模糊阴影，使用简化渐变及低不透明度接地色。两个 32px Xcode 槽位必须使用字节相同的 PNG。

光学 SVG 以目标边长的 `8×` 渲染，再用 Pillow `BOX` 面积平均到目标尺寸。这是对独立目标几何的抗锯齿，不是先生成 1024 再缩小。进一步的坐标与三轮视觉检查说明见 `sources/optical-notes.md`。

64px 已检查：原图的眼高光、鼻子与开心嘴仍可辨，没有另做光学稿。最终脚本从已经渲染的 1024 主图以 `LANCZOS` 生成 64 / 128 / 256 / 512px；1024 主图本身从 SVG 以 `4×` 渲染，再用 `BOX` 降到 1024。不要把 16 / 32px 放回这条主图降采样路径。

## iOS 满幅与三个外观

三张源文件分别为 `sources/ios-light.svg`、`sources/ios-dark.svg`、`sources/ios-tinted.svg`。从主图底框内部坐标映射到 iOS 满幅坐标：

```text
s = 1024 / 823.296 = 1.243781094527363
tx = ty = -100.352 × s = -124.81592039800995
x_ios = (x_macos - 100.352) × s
y_ios = (y_macos - 100.352) × s
matrix(s 0 0 s tx ty)
```

变换加在完整 `face` 组外层，组内几何不改。浅色与深色背景矩形改为 `x=y=0`、`width=height=1024`、`rx=0`，解除 macOS 圆角裁剪；背景渐变使用同一个矩阵，以保留相对底框的位置。浅色脸组的原路径和色值保持不变。

| 输出 | 尺寸与通道 | 背景与圆角 |
| --- | --- | --- |
| `ios-appiconset/AppIcon.png` | 1024×1024，RGB，无 alpha 通道 | 满幅暖杏底；不预画圆角 |
| `ios-appiconset/AppIcon-Dark.png` | 1024×1024，RGB，无 alpha 通道 | 满幅深棕灰底；不预画圆角 |
| `ios-appiconset/AppIcon-Tinted.png` | 1024×1024，RGBA；所有像素 `R=G=B` | 删除自带背景，外围透明；不预画圆角 |

这些通道与背景约定沿用现有 `scripts/make-icon.sh --ios` 的处理方式。深色保留不透明底；着色稿是有意设计的灰度层级，透明背景交给系统。着色稿的抗锯齿、柔和阴影可以包含中间 alpha 值，不能套用菜单栏模板的二值 alpha 规则。

展示图的 iOS 圆角只是绘制的连续圆角近似遮罩，不写进交付 PNG；着色展示中的中性深底只是模拟，不代表系统着色算法或运行效果。

## 菜单栏模板

输出约定为 `menubar/menubar-template-18.png`（18pt @1x）及 `menubar/menubar-template-36.png`（18pt @2x），RGBA，RGB 均为 `0`，alpha 只能为 `0 / 255`。模板直接按整数像素绘制，不超采样，由系统反色。

模板从选中 04 单独提炼：小圆耳、大额头、两侧鼓腮、中央短冠纹、独立实色圆眼及小鼻口。额头内部留透明空间，腮内各有透明口袋；不画横跨双眼的眼罩。两档均在自己的目标网格上手工绘制，36px 不是 18px 的整数放大，18px 稍厚用于光学补偿。

| 像素结构 | 18px / @1x | 36px / @2x |
| --- | --- | --- |
| 非透明包围盒，左上含、右下不含 | `(1,2,17,16)` | `(2,4,34,33)` |
| 外轮廓宽 × 高 | `16×14` | `32×29` |
| 实色像素 | `114 / 324`，约 `35.19%` | `382 / 1296`，约 `29.48%` |
| 四邻接连通块像素数 | 外轮廓 `104`；两眼各 `4`；鼻 `2` | 外轮廓 `350`；两眼各 `16` |
| 眼睛 | 独立 `2×2` 像素块 | 按 36px 网格独立绘制的圆眼 |
| 中央冠纹 | `2×2`，与头顶相连 | `2×5`，与头顶相连 |

`sources/menubar.py` 是可重跑的像素源；`sources/menubar-18.svg`、`sources/menubar-36.svg` 从同一网格把逐行实色区间导出为整数矩形，使用 `shape-rendering="crispEdges"`。生成不使用滤镜、平滑或降采，PNG 所有像素的 RGB 都为黑色，包括透明像素。运行整个 `render.py` 会调用模板生成器；单独生成时，在交付包根目录执行 `python3 -B sources/menubar.py`。

具体结构说明见 `sources/menubar-notes.md`，浅深反色示意见 `previews/menubar-simulation.png`。系统反色需要模板图像语义；此包没有执行 `NSStatusItem` 集成验证。18px 单色稿优先保留圆耳、鼓腮和友善眼神，不承诺单靠模板即可排除其他小型啮齿动物的误读。

依赖 Python 3、Pillow、`resvg_py`；比较图使用 `/System/Library/Fonts/Supplemental/Arial Unicode.ttf`。在仓库根目录，保留整个交付包的源文件、色彩配置和目录结构后运行。下面两条适用于从 macOS 主图和映射重新派生 iOS 的流程：

```bash
python3 -B art/app-icon-exploration/2026-10-15-copymunk-final/render.py --only sources
python3 -B art/app-icon-exploration/2026-10-15-copymunk-final/render.py
```

第一条根据主 SVG 与 `DARK` / `TINTED` 映射重新生成三个 iOS SVG；第二条渲染资产、比较图和模拟图，执行本包静态检查并更新 `manifest.json`。分步入口为 `--only render`、`--only sheets`、`--only audit`、`--only manifest`。默认完整命令不会自动执行 `--only sources`。

若已独立编辑某个 iOS SVG，应只运行第二条或所需的分步渲染命令，保留该源文件；不要运行 `--only sources`，它会覆盖三个 iOS SVG。只有打算按当前主 SVG 和外观映射重新派生时才运行第一条。

不要用旧 `scripts/make-icon.sh` 生成这套定稿：它的 macOS 分支会把主图直接缩到 16 / 32px，覆盖独立光学稿；其 `--ios` 分支仍按旧图标几何画图。接入时使用本交付包中匹配槽位的文件，不把“能生成”视为已接入、已构建或系统外观验收。
